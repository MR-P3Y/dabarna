### شرط‌های Go/No-Go پیش از انتشار
1. فرمان read-only preflight روی NODE2 سبز باشد: هر چهار سرویس Production سالم، بکاپ/rollback و مسیر storage مشخص، شناسه commit کاندیدا ثابت، دیسک قابل قبول.
2. هیچ بازی فعال حساس یا تراکنش در حال پردازش در پنجره استقرار نباشد؛ این موضوع با مشاهده لحظه‌ای و بدون دست‌کاری دیتابیس کنترل شود. وضعیت Autopilot/auto-draw از قبل موجود را **تغییر ندهید**.
3. چون کاربر Staging مستقل را لازم نمی‌داند، تست واقعی تلگرام **NOT TESTED** بماند؛ این ریسک پیش از انتشار باید آشکار و جداگانه پذیرفته شود، نه اینکه PASS گزارش شود.
4. بازگشت: Image SHA ربات و بک‌اند قبلی، وضعیت storage و نسخه schema ثبت/بکاپ شود؛ PR حاوی migration مالی جدید نباشد.
5. فقط با **مجوز صریح جداگانه استقرار نسخه ۱.۰ در Production** می‌توان merge/build/deploy کرد. این سند/PR مجوز استقرار نیست.

فقط سلامت سرویس، مشاهده یک چرخه واقعی مجاز و لاگ‌های جدید کنترل شود. در صورت شکست پیام/تکرار، قابلیت جدید اضافه نکنیم؛ به نسخه پین‌شده قبلی برگردیم و incident ثبت کنیم. هیچ عملیات خودکار روی کیف پول، موجودی، فاکتورها، جوایز یا .env انجام نشود.
