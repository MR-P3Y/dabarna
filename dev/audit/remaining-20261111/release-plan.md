# برنامه انتشار و بازگشت نامزد غیرمالی

وضعیت جاری: **انتشار مجاز در ۱۳ نوامبر ۲۰۲۶ انجام شد**؛ [رسید انتشار](deployment.md) و [شواهد کنترل نهایی](deployment-verification.json) را ببینید. مراحل زیر برنامه پیش از انتشار و مبنای اجرای آن بودند. این برنامه فقط نامزد غیرمالی است. PR مدیریت آدرس رمزارز، migrationهای #32/#41 و عملیات بازپرداخت #17 خارج از انتشارند.

1. پس از تأیید مشخص Merge، Release را با همین PR به‌روزرسانی کنید. PR #51 در تاریخچه آن است؛ می‌تواند قبل از آن Merge شود یا با همین ادغام تعیین تکلیف شود. UI قدیمی #41/#43/#47 را به‌صورت پوشه‌ای کپی نکنید.
2. پیش از تأیید Deploy، SHA مبنا و دو Image ID فعلی را دوباره بخوانید. مبنای این نوبت Backend `e713ff8…` و Bot `9f2bad21…` با tag `rc-850a6db` است؛ نامزدها و شناسه کامل در `candidate-images.json` هستند. در صورت drift، متوقف و برنامه را تطبیق دهید.
3. Imageهای ساخته‌شده و تست‌شده را با checksum منتقل کنید؛ rebuilt نامشخص را معادل Image تست‌شده تلقی نکنید. Compose chain واقعی هر سرویس را از همان کانتینر استخراج کنید. فقط image تغییر کند؛ environment، شبکه، mount، worker flags و نقش‌ها برابر بمانند. فایل خام با secrets نباید در Git یا گزارش عمومی ذخیره شود.
4. برای هر نوبت مجاز، نسخه تنظیمات، imageهای قبلی و وضعیت پایدار ACK را با مجوز محدود نگه دارید. Backend باید مستقیماً با Uvicorn بالا بیاید؛ entrypoint پیش‌فرض migration/seed اجرا نشود. schema مورد انتظار 20261108_0012 است؛ این نامزد migration ندارد.
5. توقف کوتاه Bot و تعویض فقط Backend/Bot با Compose chain تأییدشده، `--no-deps --no-build --pull never` و سپس راه‌اندازی Bot. این مرحله Restart واقعی و نیازمند تأیید Deploy است؛ MySQL/Redis بازسازی نشوند. Autopilot، بازی و تراکنش‌های واقعی برای تست دست‌کاری نشوند.
6. health چهار سرویس، health/db، فایل‌های mini و token کش، رد درخواست بدون احراز هویت، حفظ تنظیمات و ACK، لاگ خطای تازه و رفتار عادی شماره‌خوان بررسی شود. روی حساب/بازی پولی واقعی آزمون مصنوعی اجرا نکنید.
7. نصب `scripts/node2-monitor.sh` جداگانه و پس از تأیید انجام شود. پیش‌شرط: hash فایل نصب‌شده `/usr/local/sbin/davarna-monitor.sh` برابر `cd6d1a326e9b196396c123fe6636ed97fe2d8d93875c0c971b01718e0db93ce5`، مالکیت/cron/state مسیرها بررسی شوند. نسخه قبلی نگه داشته شود؛ env یا مقصد Telegram تغییر نکند. ابتدا `bash -n` و بررسی state؛ هیچ پیام تست واقعی ارسال نشود. پایشگر مستقل Autopilot با hash `b3abed63…` نیازمند این جایگزینی نیست.

Rollback برنامه: Bot را متوقف کنید، دو image دقیق `rc-850a6db` همین نوبت را با Compose chain ذخیره‌شده برگردانید، مستقیم Uvicorn و سپس Bot را بالا بیاورید و health/HTTP/ACK را بررسی کنید. **volume، کیف پول، دیتابیس و ACK فعلی عقب‌گرد داده نشوند**؛ schema downgrade، seed و بازپرداخت خودکار انجام نشود. بازگردانی monitor با فایل قبلی مجوز محدود و حفظ state انجام شود. Rollback واقعی در تلاش نخست اجرا و سلامت نسخه قبلی تأیید شد؛ علت اختلاف پایان خط فایل‌های آرشیو و blob در رسید ثبت شده است. تلاش دوم پس از اصلاح دقیق کنترل hash موفق شد.

پاکسازی: فهرست `production-inventory.json` شامل حجم مسیرهای محافظت‌شده و تمام Imageهای مرتبط است. Image فعلی، Image نامزد و rollback و تمام نسخه‌هایی که وابستگی/retention آن‌ها روشن نشده باید حفظ شوند. در این مرحله فهرست حذف قطعی خالی است. تأیید پاکسازی فقط باید روی فهرست دقیق نام/ID/حجم و دوره نگهداری انجام شود؛ `docker system prune` و حذف بازگشتی کلی مجاز نیست.
