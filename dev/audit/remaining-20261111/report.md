## خروجی قابل بررسی

- مرکز اعلان با فیلتر بازی، برد، مالی، سیستم و نخوانده؛ وضعیت بارگذاری، خطا و زمان دریافت؛ حفظ اطلاعات هنگام قطع ارتباط؛ خوانده‌شدن بعد از موفقیت عمل. وضعیت خوانده‌شدن به حساب و همین دستگاه محدود است، همگام‌سازی بین دستگاه‌ها ادعا نمی‌شود.
- کارت اعلان بازی با وضعیت و قانون ذخیره‌شده؛ شکست دریافت لیست بازی مانع رسیدن اعلان مالی تازه نمی‌شود. Poll فقط هنگام بازبودن پنجره و مشاهده‌پذیری صفحه، با ادغام درخواست هم‌زمان.
- پنجره برنده بازیکن و مدیر با صف رویداد، سهم هر کارت، حفظ کارت‌های متعدد یک برنده، مبلغ شخصی تأییدپذیر و توضیح مستقل وضعیت تسویه. مجموع رویداد جایگزین سهم کاربر نمی‌شود. رویداد ناقص یا ناسازگار به‌روشنی اعلام می‌شود.
- تمرکز صفحه‌کلید، Tab/Shift+Tab، Escape، بازگشت فوکوس از رسید تو‌در‌تو، RTL، موبایل و دسکتاپ، تیره و روشن؛ انیمیشن مطابق reduced-motion. تنظیم صدا و لرزش حفظ شده است.
- پنجره اعلان نزدیک شروع از `scheduled_start_at` و تنظیم واقعی `announce_before_seconds` استفاده می‌کند؛ تاپیک مستقل شروع در صورت تنظیم، ACK مجزا دارد. زمان صفر به‌معنی تأیید شروع نیست. شروع دستی و Scheduler تغییر نکرده‌اند.
- نسخه اصلاح‌شده **همان پایشگر نصب‌شده NODE2** در `scripts/node2-monitor.sh`: هویت هشدار ثابت، قفل اجرای هم‌زمان، ACK فقط بعد از ارسال موفق، retry خطا و رفع هشدار، حفظ thresholdها. نصب با مجوز قبلی و حفظ cron انجام شد؛ اجرای طبیعی و ثبت fingerprint پس از نصب مشاهده شد.

دو skip مجموعه Backend مربوط به MySQL opt-in هستند؛ اجرای مستقل آن‌ها در سطرهای نقش‌ها و نصب تازه ثبت شده است. آزمون روی Telegram واقعی و بازی پولی واقعی اجرا نشده است. بررسی مرورگر با API شبیه‌سازی‌شده، آزمون ارتباط واقعی Telegram WebView یا ارائه‌دهنده بلاک‌چین نیست.

شکست‌های حین کار پنهان نشده‌اند: تست اولیه دو cache token قدیمی داشت که با نسخه asset جدید و حفظ assertion اصلاح شد؛ آزمون Image ابتدا وابستگی pytest و مسیر فایل‌های قرارداد بین Backend/Bot را نداشت، سپس ابزار تست خالص Python و فایل‌های قرارداد فقط‌خواندنی متصل شدند. هیچ کد برنامه‌ای در Image برای عبور تست جایگزین نشد. ساخت نخست با `FROM sha256:...` در BuildKit به نام مخزن تفسیر شد؛ runner اکنون tag محلی را **پس از کنترل Image ID دقیق** استفاده می‌کند. خروجی نهایی ساخت و تست موفق است.

## مرزهای باقیمانده

شناسه واقعی تاپیک اختصاصی شروع هنوز تأیید و تنظیم نشده است؛ هیچ تاپیک ساخته/جابجا نشده. زمان‌بندی ۵ دقیقه‌ای وقتی Backend فقط ۳۰ ثانیه مهلت داده ممکن نیست و وعده داده نمی‌شود. Delivery ACK تلاش تکرارشونده و پایدار می‌دهد، اما crash پس از پذیرش Telegram و پیش از ذخیره ACK همچنان می‌تواند پیام تکراری بسازد؛ exactly-once ادعا نمی‌شود.

در خواندن سرور در **2026-11-12 15:23 UTC** هر چهار سرویس healthy و restart=0 بودند؛ [فهرست فقط‌خواندنی](production-inventory.json) ۳۹ Image مرتبط و ۵ مسیر محافظت‌شده را ثبت کرده است. هیچ فایل، Image، backup، receipt، ledger یا ACK حذف نشده. پاکسازی مخرب و جابه‌جایی مقصد مالی انجام نشده‌اند؛ شماره #26 در بخش حذف فایل‌ها و Imageها هنوز کامل محسوب نمی‌شود. انتشار عملیاتی غیرمالی در ۱۳ نوامبر مطابق رسید جداگانه انجام شد.
