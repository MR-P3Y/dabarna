## متن‌ها و Endpointهای سازگاری

فهرست متن‌ها و مسیر و شماره خط در text-inventory.md آمده است. متن‌های فاقد وابستگی به قانون، متن‌های مالی و متن‌های شرطی قانون مشخص شده‌اند. شرط‌های قانون در routerها، keyboards، services و notifier مرور شدند. راهنمای تورنا سهم ثابت صندوق را وعده نمی‌دهد. عنوان سطح از قانون برد جداست.

Endpointهای /games/{id}/group-message، /group-message/plain و /my-cards/message باقی هستند. در جست‌وجوی مصرف‌کنندگان داخل مخزن، فراخوانی خارجیِ سازگاری قابل اثبات نیست. حذف نشدند و سازنده‌های پیام و preview آن‌ها اصلاح شدند.

استخراج AST شامل قطعات f-string و بعضی متن‌های داخلی است. ارزیابی ایستا و آزمون‌های نماینده، تضمین اجرای تمام ترکیب‌های ممکن داده و callback نیست.

## محدودیت Delivery ACK

ارسال عادی، retry مقصد ناموفق و restart با ACK ثبت‌شده تکرار نمی‌شوند. test_crash_after_telegram_ack_before_persist_can_duplicate نیز عمداً اجرا شده و نشان می‌دهد crash پس از قبول پیام Telegram و پیش از ذخیره ACK می‌تواند یک پیام را تکرار کند. Telegram sendMessage کلید idempotency ندارد. تضمین exactly-once برای این فاصله ارائه نمی‌شود. همین محدودیت باید هنگام تصمیم انتشار لحاظ شود؛ با حذف assertion یا علامت‌زدن پیام پیش از ارسال پنهان نشده است.

## برنامه انتشار و بازگشت

پس از تأیید جداگانه مالک، از commit تأییدشده دو image immutable برای backend و bot ساخته شود. همان imageها در staging با MySQL و Redis مستقل، تنظیمات مصنوعی و Mock Bot آزمایش شوند. نسخه schema و assetها، نقش‌ها، scheduled_start_at و ذخیره ACK بررسی شوند.

پیش از انتشار، image IDهای واقعی، زنجیره Compose و تنظیمات runtime خوانده و با مبنای گزارش مقایسه شوند. در صورت drift، برنامه با نسخه جدید تطبیق داده شود. اسکریپت قدیمی #46 به‌طور مستقیم برای این نامزد قابل استفاده نیست.

اجرای پیش‌فرض Dockerfile شامل alembic و seed است. انتشار این نامزد باید فرمان startup بازبینی‌شده داشته باشد تا Migration یا seed ناخواسته روی داده واقعی اجرا نشود. تغییر Migration این PR فقط تعریف تاریخی 0001 برای نصب تازه است؛ هیچ revision جدید برای تغییر دیتابیس موجود اضافه نشده است.

برای Rollback، imageهای دقیق backend و bot ثبت‌شده در همان نوبت انتشار بازیابی شوند و volume دیتابیس، receipt و ACK حفظ شود. هیچ downgrade دیتابیس یا بازپرداخت خودکار بخشی از rollback نیست. سلامت HTTP، مجوزها، پیام‌های pending و تداوم شماره‌خوان بررسی شود. عملیات deploy و rollback هر دو نیازمند تأیید صریح مالک هستند.
