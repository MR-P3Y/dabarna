# اصلاح تم روز و ثبات فرم مدیریت — ۱۴ نوامبر ۲۰۲۶

دو ایراد گزارش‌شده کاربر در شاخه Integration اصلاح شدند؛ روی Production منتشر نشده‌اند.

1. پنل `.system-game-clock-panel` وکارت‌های readiness وclock رنگ‌های تیره ثابت داشتند. تم روز اکنون پس‌زمینه روشن، کارت سفید، متن وdigit تیره، رنگ خوانای انتظار/اجرا وtrack روشن دارد. تم شب حفظ شد؛ cache token هر دو فایلCSS/JS تغییر کرد.
2. `renderAdminAutopilotConfig` در هرpoll کل`innerHTML` را جایگزین می‌کرد؛ `<details>` باز بسته می‌شد. همچنینforce-refresh وذخیره یک سطح،dirty کل فرم را پاک می‌کردند. اکنون تطبیق DOM به تفکیک سطح است: فرم بدون تغییر یا دارایfocus/draft حفظ می‌شود؛ تغییر داده تمیز ازسرور با حفظopen دسته و تنظیمات پیشرفته اعمال می‌شود.
3. پیش‌نویس‌ها به تفکیک سطح ثبت می‌شوند. ذخیرهLOW بهHIGH دست نمی‌زند؛ ویرایش تازه درحینPUT حفظ وبا پیام «هنوز ذخیره نشده» مشخص می‌شود. پاسخGET قدیمی پس ازذخیره باepoch رد می‌شود. خطای شبکه فرم را پاک نمی‌کند. بازخوانی دستی نیزdraft را دور نمی‌ریزد. مجوزکمیسیونِ لغوشده حتی رویdraft قدیمی غیرفعال می‌شود؛ Backend همچنان مرجع مجوز است.

تست مرورگر واقعی Chrome باAPI شبیه‌سازی‌شده:

- تغییر داده سرور، بازماندن دسته و بخش تنظیمات بیشتر؛ به‌روزشدن داده تمیز.
- حفظ همانinput،focus،محلcursor ومقدارذخیره‌نشده هنگامpoll وforce-refresh.
- خطای503 و بازیابی بدون حذففرم.
- GET قدیمی هم‌زمان باPUT، تایپ جدید درحین ذخیره، ذخیره مستقل دو سطح.
- بازخوانی ازدکمه واقعی و لغومجوزکمیسیون رویdraft.
- screenshot تم روز درموبایل390×844 ودسکتاپ1280×1000، screenshot تمشب، کنترل computed colors.
- **PASS؛دوPUT کاملاًMock،صفرشبکه واقعی،صفرخطایJavaScript.**

آزمون ابتدا نشان داد signature درattribute HTML درست ذخیره نمی‌شود؛ به‌جایJSON داخلHTML، اکنونdataset مستقیماًرویDOM تنظیم می‌شود. همانassertion به‌روزرسانی داده تمیز حفظ شد و اجرای نهایی موفق بود. پس ازاصلاح، مرورگرهایpacing وcrypto وهر11مجموعهJS هم دوباره موفق شدند. هیچ تستی برای پوشاندن شکست حذف نشد.
