# کنترل کیفیت و دروازه انتشار UI/UX دبرنای طوفان — موج ۵

**وضعیت:** نسخه توسعه. موفقیت تست‌های اختصاصی به معنای مجوز انتشار نیست.

## یافته‌های موج ۵ و اصلاحات ثبت‌شده

1. تابع `switchToView("cards")` بارگذاری خودکار را آغاز می‌کرد، درحالی‌که لینک مستقیم «کارت‌های من» و اعلان برنده خودشان نیز `refreshCards()` را صدا می‌زدند. حالا این مسیرها فقط یک درخواست بارگذاری شروع می‌کنند و polling دوره‌ای محفوظ می‌ماند.
2. تابع `notificationRoute` برای اعلان نامشخص، مسیر پیش‌فرض کیف پول در نظر می‌گرفت. اکنون مسیرهای صریح و معتبر مالی (`wallet`، بخش‌های واریز/برداشت، `open_receipt`) به کیف پول می‌روند؛ مسیر ناشناخته با پیام روشن به بازی‌ها برمی‌گردد.
3. اعلان‌ها پیش از موفقیت هدایت یا بازشدن رسید، «خوانده شد» علامت می‌خوردند. اکنون فقط بعد از موفقیت این کار انجام می‌شود؛ خطا باعث از دست رفتن وضعیت خوانده‌نشده نمی‌شود.
4. تست `backend/tests/js/test_navigation_regressions_wave5.mjs` مسیرهای مالی، برنده، ناشناخته و بارگذاری تکراری را در محیط شبیه‌سازی‌شده کنترل می‌کند.

## اجرای دروازه تست ایزوله

از ریشه `/opt/davarna-v2` روی شاخه `feature/ui-ux-refresh-tambola-v2-20261106`:

```bash
git pull --ff-only origin feature/ui-ux-refresh-tambola-v2-20261106
bash dev/ux-preview/validate-wave5.sh
```

این اسکریپت با تصاویر Docker محلی و `--network none`، تست‌های JavaScript، Backend و Telegram Bot را بدون اتصال به Production اجرا می‌کند و هیچ سرویس/کانتینر اصلی را ری‌استارت یا استقرار نمی‌دهد. فایل‌های `.env.prod` نباید به کانتینر تست ارسال شوند.

## مواردی که هنوز باید قبل از انتشار کنترل شوند

- **تست تصویری واقعی تلگرام/مرورگر** روی Staging با HTTPS و Bot آزمایشی مستقل؛ پیش‌نمایش HTML ایستا جایگزین آن نیست.
- **آزمون مالی و همزمانی** از جمله چند برنده هم‌زمان، retry، لغو لابی، استرداد وجه، دوبار کلیک و قطع شبکه با داده‌های آزمایشی. این موارد با تست‌های موج‌های UI/UX اثبات نشده‌اند.
- **محدودیت‌ها و امنیت سرور:** محافظ UI جایگزین RBAC و کنترل ایدمپوتنسی Backend نیست.
- **قوانین پین‌شده در تاپیک ادمین:** تغییر متن سورس به‌تنهایی پیام پین‌شده قدیمی را ویرایش نمی‌کند؛ تغییر marker یا ارسال مجدد بدون برنامه ممکن است پست تکراری بسازد.
- **استقرار Production فقط پس از تایید QA:** بررسی بکاپ، تهیه نسخه ایمیج جدید، حفظ Compose overlay و feature flags، بررسی migration و امکان rollback، مشاهده health و log، تأیید عدم فعال‌سازی Autopilot ناخواسته.

**معیار خروج:** تمامی تست‌های اتوماتیک + سناریوهای دستی بحرانی باید موفق شوند. تا آن زمان نسخه اصلی تغییر نمی‌کند.
